
# 单门店汽车美容小程序 - 前端开发文档

## 1. 项目概述

本文档旨在为「景辉汽车美容公司小程序」的前端开发提供指导。前端需实现用户界面、用户交互、与后端 API 的数据通信，确保用户能够流畅地完成预约、查看订单进度等操作。

**核心目标**：

- 实现用户友好的预约下单流程。
- 清晰展示订单状态和洗车服务进程（四个阶段）。
- 区分并支持预约单和现场单的查询与展示。
- 确保与后端 API 的顺畅对接和数据同步。
------

## 2. 核心页面与功能实现

### 2.1 首页 (`pages/index/index`)

- UI 布局：
  - 顶部 Banner (可选)
  - 核心服务入口（如 "预约洗车" 按钮）
  - 门店信息展示（名称、地址、联系电话、营业时间）
  - 可选：优惠活动、快捷查单入口 (现场单)

- 交互逻辑：
  - 点击 "预约洗车" 进入预约流程。
  - 点击门店信息可触发地图导航或拨打电话。
  - 若有查单入口，输入订单号/手机号跳转至订单详情页。

- API 对接：
  - `GET /api/store/info`：获取门店基本信息。
  - `GET /api/promotions` (可选)：获取活动信息。

### 2.2 预约下单流程

此流程可能包含多个页面或步骤：

#### a. 服务选择页 (`pages/booking/service`)

- UI 布局：
  - 服务列表：展示服务名称、价格、预计耗时、简介。
  - 使用卡片或列表形式。

- 交互逻辑：
  - 用户选择一项或多项服务（注意：当前需求以洗车为主，但需考虑扩展性）。
  - 选中后高亮显示。
  - 底部显示已选服务总价，并有 "下一步" 或 "选择时间" 按钮。

- API 对接：
  - `GET /api/services`: 获取所有可预约服务列表及详情。

#### b. 时间选择页 (`pages/booking/time`)

- UI 布局：
  - 日期选择器 (如日历组件)，仅可选未来 N 天（由后端配置）。
  - 时间段选择：根据选定日期，展示当天可预约的时间段 (如 09:00-10:00)。
  - 需明确标示哪些时间段已满或不可选。

- 交互逻辑：
  - 用户选择日期后，动态加载该日期的时间段。
  - 用户选择一个时间段。
  - 点击 "下一步" 或 "填写车辆信息"。

- API 对接：
  - `GET /api/available_slots?date=YYYY-MM-DD&service_ids=...`: 根据日期和服务获取可用时间段。

#### c. 车辆信息与确认页 (`pages/booking/confirm`)

- UI 布局：
  - 车辆信息输入/选择：
    - 若用户已保存车辆，提供选择列表。
    - 若无，提供输入框（车牌号、车型、颜色等）。
    - "保存车辆信息" 选项。
  - 订单信息汇总：展示所选服务、时间、车辆信息、总金额。
  - 支付方式：默认微信支付。

- 交互逻辑：
  - 用户确认信息无误。
  - 点击 "提交预约并支付"。
  - 调用微信支付接口。
  - 支付成功后跳转到订单详情页或订单列表页，提示预约成功。
  - 支付失败给出相应提示。

- API 对接：
  - `GET /api/user/vehicles`：获取用户已保存的车辆列表。
  - `POST /api/appointment/create`：提交预约信息，后端生成订单并返回支付参数。
  - 调用 `wx.requestPayment` 发起支付。
  - `POST /api/user/vehicles/add` (可选)：保存新车辆信息。

### 2.3 我的订单列表页 (`pages/order/list`)
- UI 布局：
  - 顶部 Tab 切换：全部、待到店、等待服务、洗车中、已完成 (可根据实际需要调整筛选)。
  - 订单卡片列表：
    - 显示订单类型（预约/现场 - 视觉上需区分）。
    - 服务项目概要。
    - 车牌号。
    - 预约时间 (若为预约单)。
    - 订单状态。
    - 订单金额。

- 交互逻辑：
  - 默认加载 "全部" 订单。
  - 切换 Tab 时，根据状态筛选并重新请求数据。
  - 下拉刷新加载最新订单。
  - 上拉加载更多历史订单 (分页)。
  - 点击订单卡片跳转到订单详情页。

- API 对接：
  - `GET /api/order/list?status=...&type=...&page=...&limit=...`: 获取订单列表，支持按状态、类型、分页查询。

### 2.4 订单详情页 (`pages/order/detail`)

- UI 布局：
  - 核心：订单进度展示
    - 使用 **Stepper (步骤条)** 或 **Timeline (时间轴)** 组件，清晰展示四个（或三个，对现场单）阶段。
    - 高亮当前所处阶段。
    - 各阶段状态：
      - `待到店` (预约单)：提示用户按时到店。
      - `等待服务`：提示车辆已到店，排队等候。
      - `洗车中`：提示服务正在进行。
      - `可取车/已完成`：提示服务完成，可取车。
    - (可选) 显示各阶段的时间戳。
  - 订单基本信息：订单号、订单类型、下单时间、服务项目、金额。
  - 车辆信息：车牌号、车型。
  - 预约信息 (若为预约单)：预约到店时间。
  - 操作按钮 (根据状态显示)：
    - `待到店` 状态下显示 "取消预约" 按钮 (需判断是否在可取消时间范围内)。
    - `可取车/已完成` 状态下显示 "评价" (若有评价功能)、"再次预约" 等按钮。
  - 门店信息：地址、电话 (方便联系)。

- 交互逻辑：
  - 进入页面时加载订单详情和当前状态。
  - 页面应能 **自动或手动刷新** 状态 (如：下拉刷新，或定时轮询，或 WebSocket - 与后端约定)。
  - 点击 "取消预约" 需二次确认，成功后更新页面状态或返回列表。

- API 对接：
  - `GET /api/order/detail?order_id=...`: 获取指定订单的详细信息及当前状态。
  - `POST /api/order/cancel`: 取消预约订单。
  - (轮询场景) 可能需要定期调用 `GET /api/order/detail` 或一个专门的 `GET /api/order/status?order_id=...` 接口。

### 2.5 现场下单查单页 (如果单独做入口) (`pages/lookup/index`)

- UI 布局：
  - 简单的输入框，提示用户输入手机号或订单号。
  - 查询按钮。

- 交互逻辑：
  - 输入信息后点击查询。
  - 查询成功跳转至对应的订单详情页。
  - 查询失败给出提示（如 "未找到订单"）。

- API 对接：
  - `GET /api/order/lookup?query=...`: 根据手机号或订单号查询现场订单。

## 3. 可复用组件建议

- `ServiceCard`: 服务项展示卡片。
- `TimeSlotPicker`: 时间段选择组件。
- `VehicleSelector`: 车辆选择/输入组件。
- `OrderListItem`: 订单列表项卡片。
- `OrderStatusStepper`: 订单状态步骤条/时间轴组件。
- `Loading`: 全局或局部加载状态提示。
- `Empty`: 空状态提示 (如无订单、无服务)。

------

## 4. 状态管理

- **用户认证**：管理 `token` 或 `session`，确保 API 请求的有效性。可通过 `globalData` 或状态管理库维护登录状态。
- **订单状态同步**：订单详情页的状态更新是核心。与后端协商好更新机制（轮询/WebSocket/手动刷新），前端需准确反映后端返回的最新状态。
- **表单数据**：预约流程中的表单数据建议使用页面级状态管理。

------

## 5. API 对接注意事项

- **统一处理请求**：封装 `wx.request`，统一处理基地址、请求头 (如 `Content-Type`, `Authorization`)、加载提示、错误处理和响应拦截。
- **认证**：所有需要用户登录的接口需携带认证信息。实现微信登录逻辑，获取 `code` 交给后端换取 `token` 或 `session`。
- **错误处理**：对网络错误、服务器错误 (5xx)、业务逻辑错误 (4xx) 进行捕获和用户友好的提示。
- **Loading 状态**：在 API 请求期间显示加载提示，防止用户重复操作。
- **数据格式**：与后端确认请求参数和响应数据的具体结构。

------

## 6. UI/UX 重点

- **状态清晰**：订单的四个阶段必须在视觉上清晰区分，用户能一眼看出当前进度。
- **流程顺畅**：预约流程步骤分明，引导清晰，减少用户思考负担。
- **反馈及时**：用户的操作（如点击按钮、支付、取消）需要有明确的成功、失败或加载中反馈。
- **信息简洁**：突出核心信息（如状态、时间、价格），避免信息过载。
- **一致性**：整体风格、组件样式、交互方式保持一致。
