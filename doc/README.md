## 数据库设计概述

我们采用了两个主要集合来存储数据：

### users集合

存储用户的基本信息、会员信息和账户余额。

### vehicles集合

存储用户的车辆信息，与用户表通过userId字段关联。

这种设计的优势：

- 数据结构清晰，符合数据库设计范式
- 方便单独查询和管理车辆信息
- 为未来扩展功能（如车辆维修记录）提供基础
- 改善查询性能，尤其是当用户有多辆车时

## 迁移说明

如果您之前的项目将车辆信息存储在用户表的vehicles数组中，需要执行迁移操作。请参考[数据迁移示例](migration-example.js)了解如何实现迁移。

## 数据安全

我们建议对不同集合设置不同的安全规则：

- users表：仅创建者可读写，保护用户隐私
- vehicles表：所有用户可读，仅创建者可写，便于服务提供者查看车辆信息

详细配置请参考[数据库设置指南](database-setup.md)。
