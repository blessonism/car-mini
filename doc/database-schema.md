# 汽车服务小程序数据库结构设计

## 概述

本文档描述了汽车服务小程序的数据库表结构设计，包括用户表（users）和车辆表（vehicles）的字段定义及用途。

## 用户表（users）

用户表存储所有注册用户的基本信息和会员相关信息。

| 字段名      | 类型   | 必填 | 描述                           |
| ----------- | ------ | ---- | ------------------------------ |
| \_id        | String | 是   | 文档唯一ID，系统自动生成       |
| \_openid    | String | 是   | 用户的微信OpenID，用于身份识别 |
| createTime  | Date   | 是   | 用户创建时间                   |
| updateTime  | Date   | 是   | 用户信息更新时间               |
| nickName    | String | 否   | 用户微信昵称                   |
| avatarUrl   | String | 否   | 用户微信头像URL                |
| gender      | Number | 否   | 用户性别：0-未知，1-男，2-女   |
| phone       | String | 否   | 用户手机号码                   |
| name        | String | 否   | 用户真实姓名或自定义昵称       |
| memberLevel | String | 是   | 会员等级，默认"普通会员"       |
| balance     | String | 是   | 钱包余额，默认"0.00"           |

### 说明：

1. **\_openid** 字段由微信登录时自动获取
2. **nickName**, **avatarUrl**, **gender** 等微信个人信息需要用户授权获取
3. **phone** 和 **name** 需要用户手动填写
4. **balance** 字段以字符串形式存储金额，避免浮点数精度问题

## 车辆表（vehicles）

车辆表存储用户添加的所有车辆信息，与用户表通过用户ID关联。

| 字段名     | 类型   | 必填 | 描述                        |
| ---------- | ------ | ---- | --------------------------- |
| \_id       | String | 是   | 文档唯一ID，系统自动生成    |
| \_openid   | String | 是   | 车辆所属用户的微信OpenID    |
| userId     | String | 是   | 关联的用户表ID              |
| createTime | Date   | 是   | 车辆信息创建时间            |
| updateTime | Date   | 是   | 车辆信息更新时间            |
| plate      | String | 是   | 车牌号，如"京A12345"        |
| brand      | String | 是   | 车辆品牌，如"奔驰"、"宝马"  |
| model      | String | 是   | 车型/型号，如"C260L"、"5系" |
| color      | String | 是   | 车身颜色，如"黑色"、"白色"  |

### 说明：

1. 每个用户可以添加多辆车辆，通过 **userId** 和 **\_openid** 双重关联确保数据安全
2. **plate** 字段存储完整车牌号，包含省份简称
3. **brand** 和 **model** 字段由用户手动输入，未来可考虑提供预设选项
4. 通过将车辆信息独立为单独的表，便于未来扩展更多与车辆相关的功能

## 表关系

- 一个用户（users表）可以拥有多辆车辆（vehicles表）
- vehicles表通过userId字段关联到users表的\_id字段
- 同时也通过\_openid字段保持与用户的关联，便于权限控制

## 未来可能的扩展

1. **车辆维修记录表**：记录每辆车的维修历史
2. **保养提醒表**：根据车辆信息生成保养提醒
3. **预约服务表**：用户预约的各类服务记录
4. **交易记录表**：用户充值、消费等财务记录

## 安全控制

建议对两个表设置如下安全规则：

- users表：仅创建者可读写
- vehicles表：所有用户可读，仅创建者可写

这样设计既保护了用户隐私，又便于服务人员查看车辆基本信息。
